# Research

What we've learned from outside the design itself: competitor references, how similar products work, interviews, meetings and user input.

**Owner:** Definition needed.

## When to read

Before proposing a new pattern or flow. The answer may already be here.

## When to write

A source has been studied, a meeting has happened, or the designer shares something worth keeping.

## Rules

- Store **summaries and takeaways**, not raw dumps. No transcripts, full chat exports or pasted web pages. Link to the source instead.
- One file per topic or source. Start each with its date and source.
- End every file with **What we took**: the specific choice it influenced. Link the decision in `../decisions/` when there is one. If nothing was taken yet, write "Nothing yet."
- Screenshots go in `research/images/`, named `<source>-<topic>.png`.
- Meeting notes go in `meetings/`. See `meetings/CLAUDE.md`.
- Add a row to the index in `README.md` for every new file.
- Mark anything unconfirmed **Unknown**.

## Format

```
# <Topic>

- **Date:** YYYY-MM-DD
- **Source:** link or name

## What we saw
Short summary, in your own words.

## What we took
The choice it influenced, and the decision number if there is one.
```

# Work log (optional)

A running record of finished work. It answers "what have we done on this project?" months later, and feeds daily and weekly updates. **Skip this folder if your team doesn't need it.** Nothing else depends on it.

## Rules

- **One file per month:** `YYYY-MM.md`. Entries go at the bottom, newest last. Never rewrite history. Correct an entry with a dated note under it.
- **One entry per completed task or deliverable,** not per session. A task is something you could name in a check-in.
- **Approve, then append.** Claude drafts an entry when a task finishes. The designer says "log it", edits it, or skips it. Nothing is added unreviewed.
- **Link, don't paste.** Point to the decision, spec, Figma page or ticket.
- Mark anything unconfirmed **Unknown**.

## Entry format

```
### YYYY-MM-DD · <ticket, if any> · <what was done>
- **Type:** discovery · spec · research · decision · flow · screens · component · docs · handoff · review · other
- **Output:** links (decision, spec, Figma page, ticket)
- **Claude did / Designer did:** one line each
- **Notes:** blockers, rework, what was left out
```

Story points and time-saved estimates are **Definition needed**: the agency hasn't set a standard for them yet. Don't add them until it does.
